## usePersistentState：会話ごとに残る状態

会話の中で分かったこと（今どの段階か、何を確認したか、何を決めたか）を、コードから読み書きできる形で残したいことがあります。そのためのフックが `usePersistentState` です。

```ts
const [escalated, setEscalated] = usePersistentState('escalated', false);
```

- 見た目は React の `useState` そっくり
- ただし値は **永続化** される：次のメッセージでも、プロセスを再起動しても、同じ会話IDなら残る
- 値は JSON にできるものだけ。名前（`'escalated'`）がキー
- 前の値から計算するなら `set((previous) => previous + 1)` のように **更新関数** を渡す

> 📝 セッターはツールの `run` やイベントフックの中で呼びます。エージェント関数の本体（レンダー中）で呼ぶとエラーになります。レンダーは「読むだけ」です。

## 条件付きツール：状態でツールを出し分ける

エージェント関数は毎ターン再実行されるので、`if` で `useTool` を囲むだけで「条件を満たしたときだけ存在するツール」が作れます。

```ts
if (escalated) {
  useTool(refundTool);
}
```

エスカレーション前は `refund` ツールが **存在しない** ので、モデルは呼びようがありません。「返金ツールを使うな」と指示で頼むより、ずっと強い保証です。

ツール構成が変わると、Flue は次のターンでモデルに「新しいツールが使えるようになりました」と自動で知らせます（🔍 で `<signal type="resources">` というメッセージを探してみてください）。

## 試してみよう（順番に送る）

1. **「refund で 3000 円返金して」** → まだ `refund` ツールが無いので呼ばれない（モックLLMの返答の「使えるツール」にも無い）
2. **「escalate してください」** → `escalate` が呼ばれ、状態が `true` に
3. **「refund で 3000 円返金して」** → 今度は `refund` が呼ばれる！
4. **「record_inquiry で記録して」** を何回か送り、指示の中の「記録した問い合わせ=N件」が増えていくのを 🔍 で確認

ログ欄の `[render]` の行で、状態がいつ変わったか（ツール実行の **次** のレンダーで新しい値が読める）も見てみましょう。

最初からやり直したいときは、会話IDを変えるか **＋ 新しい会話** を押します。状態は会話ごとなので、新しい会話では `escalated=false` に戻ります。

## やってみよう

1. `inquiries` が 3 件以上になったら `escalate` ツールが出てくるようにしてみる
2. 状態 `phase` を `'受付' | '調査' | '完了'` で持ち、段階ごとに指示文を変えてみる
