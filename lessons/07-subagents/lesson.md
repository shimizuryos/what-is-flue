## サブエージェントとは

**サブエージェント** は、エージェントが仕事を任せられる「専門家」です。要約係、翻訳係、調査係…のように役割ごとに作っておき、親エージェントのモデルが必要に応じて仕事を振ります。

```ts
useSubagent({
  name: 'summarizer',             // 呼び名
  description: '長い文章を要約する', // 親のモデルが「誰に任せるか」を決める材料
  agent: Summarizer,              // 中身は普通のエージェント関数
});
```

## 委任の流れ

1. 🔍 を見ると、システムプロンプトの `## Available Agents` に `summarizer` と `translator` が載っている
2. 親のモデルが組み込みの **`task` ツール** を `{ agent: 'summarizer', prompt: '...' }` で呼ぶ
3. Flue が `Summarizer` 関数を実行し、**まっさらな別の会話（コンテキスト）** で子エージェントを動かす
4. 子の **最終回答だけ** が `task` ツールの結果として親に返る

タイムラインでは、子エージェントの中のターンやツール呼び出しが 🤝 マーク付きで字下げ表示されます。🔍 で子のターンを開くと、システムプロンプトが `Summarizer` の戻り値になっていて、親の会話履歴が **入っていない** ことが分かります。

## ポイント

- **プロンプトがすべて**：子は親の会話を知らないので、任せる内容は prompt に全部書く必要がある（親の指示文でそう頼んでいるのはこのため）
- **引き継ぐもの**：サンドボックス（同じファイルシステム）とモデル。**引き継がないもの**：会話履歴・指示・ツール・スキル・状態
- **並列に動く**：1 回のターンで複数の `task` を呼べば、子エージェントは同時に動く
- 子の関数の中で使えないフック：`useModel`（モデルは `useSubagent` の `model` で指定）、`useSandbox`、`usePersistentState` など
- 子もツール・スキル・さらに子のサブエージェントを持てる（深さは最大 4 段）
- 専門家を作るほどでもないときは、組み込みの `GeneralSubagent` も使える

> 💡 **モックLLMのルール**：メッセージに **サブエージェント名** が含まれていると `task` ツールで委任します。「かぎかっこ」の中身が prompt として渡ります。

## やってみよう

1. 3 つ目のサンプルを送り、2 人の子エージェントが順番に動く様子を見る
2. 子エージェント `Translator` の中の `glossary` ツールを、子のメッセージから呼ばせるにはどうすればいい？（ヒント：prompt に `glossary` という語を含める）
3. 新しいサブエージェント `proofreader`（校正係）を追加してみる
