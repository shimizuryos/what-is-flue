## ツールとは

**ツール** は、あなたが書いた関数をモデルが呼べるようにしたものです。注文を調べる、チケットを作る、返金する…など、アプリのコードを実行させたいときに使います。

- **モデルが決めること**：いつ・どの引数でツールを呼ぶか
- **あなたのコードが決めること**：呼ばれたときに何が起きるか

ツール定義は 4 つの部品でできています。

| 部品 | 役割 |
| --- | --- |
| `name` | モデルが呼ぶときの名前 |
| `description` | モデルにとって唯一の説明書。**曖昧だと正しく呼ばれない** |
| `input` | 引数のスキーマ（[Valibot](https://valibot.dev)）。検証に失敗すると `run` は呼ばれず、モデルにエラーが返る |
| `run` | 実行される関数。`{ output }` を返す（文字列を返すのは `{ output: 文字列 }` の省略形） |

`defineTool()` で定義して別ファイルに置き、エージェントで `useTool()` するのが基本形です。1 回しか使わないなら `useTool({ ... })` にその場で書いても OK です。

## 1 回のメッセージで何が起きるか

1. エージェント関数が実行され、ツール一覧と指示が組み立てられる
2. モデルが「`lookup_order` を `{ orderId: "A-1001" }` で呼ぶ」と決める
3. Flue が引数を検証し、`run` を実行し、結果をモデルに返す
4. **エージェント関数がもう一度実行され**、モデルが結果を読んで返答を書く

実行結果のタイムラインで、🔧 ツール呼び出し → 結果 → 返答 の流れを確認しましょう。ログ欄には `log.info()` の出力も表示されます。

> 💡 **モックLLMのルール**：メッセージに **ツール名**（`lookup_order` など）が含まれていると、そのツールを呼びます。引数はスキーマを見て、メッセージ中の ID（`A-1001`）や数字、「かぎかっこ」の中身から推測します。本物の LLM なら「A-1001 の注文どうなってる？」のような自然な文でもツールを選びます。

## エラーもモデルに返される

`Z-9999` のような存在しない注文を調べると、`run` の中で `throw` したエラーが **ツールのエラー結果としてモデルに返ります**。エージェントは止まらず、モデルは「見つかりませんでした」とユーザーに伝えたり、別の方法を試したりできます。

## ツール一覧に注目

🔍 **モデルへの入力** の「ツール」を見ると、`lookup_order` の `parameters` が JSON Schema に変換されて送られているのが分かります。モデルが見ているのは **name・description・parameters だけ** です。

## やってみよう

1. `src/shared/orders.ts` に注文を追加して、調べてみる
2. `lookup_order` の `input` を `v.object({ orderId: v.pipe(v.string(), v.regex(/^[A-Z]-\d{4}$/)) })` にして、`lookup_order で注文 abc を調べて` を送る（検証エラーがモデルに返る）
3. 新しいツール `cancel_order` を作って `useTool` し、`cancel_order で A-1002 をキャンセルして` を送る
